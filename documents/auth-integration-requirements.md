# AuthContext統合要件定義書

## プロジェクト概要
オンボーディング完了後の認証状態維持とチャットボット機能におけるAuthContext統合を実装する。

## 現状分析

### 既存実装の状況
- ✅ **AuthProvider**: 全アプリケーションレベルで実装済み（`src/app/layout.tsx`）
- ✅ **AuthContext**: 完全な認証状態管理機能を実装済み（`src/contexts/AuthContext.tsx`）
- ✅ **セッション管理API**: `/api/user/session` でバックエンド連携実装済み
- ✅ **ログインフロー**: `login()` 関数で認証状態を正しく設定
- ✅ **永続化**: localStorageを使った `registered_user_id` の保存/復元機能
- ❌ **チャットボット統合**: `/home` ページで `user_id: 1` のダミーIDを使用

### 問題点
1. **チャットボット機能**: 認証状態を無視してダミーID（`user_id: 1`）を使用
2. **レシピ機能**: 既に適切にAuthContext統合済み（ダミーIDは未認証時のフォールバック）
3. オンボード完了後の認証状態とAPI呼び出しが連携していない（チャットボットのみ）

### データフロー

```
1. ページロード
   ↓
2. AuthProvider初期化
   ↓
3. localStorage確認 ('registered_user_id')
   ↓
4. /api/user/session でセッション確認
   ↓
5. 成功 → 認証状態設定 | 失敗 → localStorage削除
   ↓
6. チャットボットで認証済みuser_id使用
   ↓
7. API呼び出し (transcribe, feedback) に実user_id送信
```

### 型定義

```typescript
interface User {
  id: number
  nickname?: string
  email?: string
  isAuthenticated: boolean
}

interface AuthContextType {
  user: User | null
  login: (userData: User) => void
  logout: () => void
  updateUser: (userData: Partial<User>) => void
  isLoading: boolean
}
```
